## Alpha NuvioWeb

- Vanilla browser JS with esbuild, HLS.js and DASH.js, producing a static dist bundle. See [package.json](https://github.com/alphasquare404/NuvioWeb/blob/web/package.json), [build script](https://github.com/alphasquare404/NuvioWeb/blob/web/scripts/build.mjs).
- Nuvio-compatible account integration already exists: [auth manager](https://github.com/alphasquare404/NuvioWeb/blob/web/js/core/auth/authManager.js) uses Supabase-compatible password/session refresh, QR/device flows and get_sync_owner; [session store](https://github.com/alphasquare404/NuvioWeb/blob/web/js/core/storage/sessionStore.js) stores access/refresh tokens in localStorage, requiring XSS/token security review.
- HTTP/Stremio-style [add-on repository](https://github.com/alphasquare404/NuvioWeb/blob/web/js/data/repository/addonRepository.js) tracks configured manifests. [Stream repository](https://github.com/alphasquare404/NuvioWeb/blob/web/js/data/repository/streamRepository.js) merges add-on sources and plugin sources.
- Its separate [JS plugin runtime](https://github.com/alphasquare404/NuvioWeb/blob/web/js/core/player/pluginRuntime.js) currently expands URL templates, not a full sandboxed JavaScript scraper runtime.
- [Playback engines](https://github.com/alphasquare404/NuvioWeb/tree/web/js/core/player/engines) implement native video, HLS.js and DASH.js paths. They cannot override browser codec or DRM restrictions.
- [Docker Compose](https://github.com/alphasquare404/NuvioWeb/blob/web/docker-compose.yml) includes a web frontend plus Trakt auth, debrid API and external playback-return sidecars; a static-only host cannot preserve every sidecar-backed capability.
- [Auth config](https://github.com/alphasquare404/NuvioWeb/blob/web/js/core/auth/supabaseAuthFetch.js) calls the existing hosted Nuvio backend and fallback endpoint; availability/terms/capacity not independently approved.

## Falcon NuvioWeb

- [Local audio engine](https://github.com/falcononrails/NuvioWeb/blob/nightly/js/core/player/engines/localAudioEngine.js) uses AVPlayer/WebCodecs/WASM for selected audio/container cases; requires tested browser APIs and does not bypass CORS.
- [FFmpeg playback bridge](https://github.com/falcononrails/NuvioWeb/blob/nightly/services/playback-bridge/server.mjs) is optional server processing, includes Nuvio token verification, and relies on native FFmpeg. Use its security patterns as an input, not a blanket security endorsement.
- [Upstream sync policy](https://github.com/falcononrails/NuvioWeb/blob/nightly/docs/upstream-sync.md) describes review boundaries: blindly merging upstream caused conflicts.
- Falcon nightly diverges substantially from Alpha; port features selectively rather than merging indiscriminately.

## GYK fork

- [Plugin manager](https://github.com/GYK-Studio/NuvioWeb/blob/main/js/core/player/pluginManager.js), [Web Worker](https://github.com/GYK-Studio/NuvioWeb/blob/main/js/core/player/pluginWorker.js), and [runtime](https://github.com/GYK-Studio/NuvioWeb/blob/main/js/core/player/pluginRuntime.js) implement a much richer JS scraper path using a QuickJS/WASM isolated runtime.
- [Plugin network client](https://github.com/GYK-Studio/NuvioWeb/blob/main/js/platform/pluginServiceClient.js) attempts direct fetch or an optional /api/providers/fetch proxy. Cross-origin/CORS limits remain; an unbounded hosted proxy is unacceptable.
- Review URL filtering, redirects, private-network access, code size, execution time, plugin API parity and licensing before reuse.

## Orochi

- SvelteKit 3/Svelte 5/Bun-based site with sessions, SQLite and modern testing. This is not a direct static replacement and increases server-state requirements. Reported license AGPL-3.0-or-later; code reuse needs independent licensing review.
- See [repository](https://github.com/orochibraru/nuvio-web).

## Risk-ranked findings

1. **Critical**: authorization to depend on Nuvio public hosted login/sync, and account identity verification in premium control plane.
2. **Critical**: malicious plugins, SSRF, arbitrary network destinations and uncontrolled paid FFmpeg workloads.
3. **High**: browser/OS codec capabilities, 4K/HDR/Atmos/Dolby Vision profiles, CORS, HTTPS mixed-content policies, source headers.
4. **High**: public scale and expense of video ingress/egress; avoid centralized media relay.
5. **High**: GPL/AGPL attribution and dependency compatibility.
6. **Medium**: PWA caching/stale assets and non-serverless external-return state.
7. **Medium**: upstream drift and regressions across forks/native Enhanced features.

## Recommendation

Start from pinned Alpha web. Preserve license/history/provenance. Prototype Falcon local audio and GYK plugins in isolated, benchmarked branches. Separate authenticated metadata/control APIs from dedicated media workers. Do not claim codec parity without reproducible playback fixture evidence.
