### Binding architecture

1. **Existing Nuvio identity:** authorization principal is the configured upstream trust domain plus authoritative subject. Sync owner, profile index, email and decoded JWT payloads are not substitutes.
2. **Local before remote:** compatible direct playback and browser-local recovery remain available independently of compute.
3. **User-owned compute:** the user chooses and pairs their own executor. NuvioWeb charges no operator processing fee for that path; the user remains responsible for their infrastructure costs.
4. **No operator media relay:** shared control endpoints carry bounded control messages only. Source and output bytes travel directly between authorized sources, the selected user-owned executor and the browser.
5. **Hosted compute gating:** any later hosted job requires explicit customer price/credit authorization, successful reservation and enforceable hard caps. #13 implements none of those operations and rejects hosted execution.
6. **Restricted processing:** authorized media only; no DRM bypass, arbitrary shell commands, general-purpose fetch endpoint or unrestricted URL proxy.
7. **Evidence limits:** synthetic lifecycle tests cannot establish container isolation, live Nuvio session verification, browser reachability or codec support.

## 2. Proposed version-1 protocol

### 2.1 Module and transport

Create a standalone `packages/compute-protocol` module. Its public interface covers message validation, version negotiation and deterministic lifecycle decisions. Storage, clocks, signing, transport and execution are supplied through adapters.

**Wire profile:** HTTPS, canonical UTF-8 JSON, fixed operation routes, no cookies, no redirects and `Cache-Control: no-store`. Agent control connectivity is outbound polling; WebSocket transport is deferred.

Proposed future routes, specified here but not deployed:

| Route | Purpose |
| --- | --- |
| `POST /compute/v1/negotiate` | Select an exact protocol version and capabilities. |
| `POST /compute/v1/jobs` | Submit an authorized job. |
| `GET /compute/v1/jobs/{jobId}` | Return the caller’s authorized snapshot. |
| `POST /compute/v1/jobs/{jobId}/cancel` | Request cancellation idempotently. |
| `POST /compute/v1/agents/{agentId}/poll` | Receive bounded offers, cancellation and reconciliation commands. |
| `POST /compute/v1/agents/{agentId}/events` | Submit acceptance, start, progress, result, error and cleanup events. |
| `POST /compute/v1/jobs/{jobId}/artifact-access` | Authorize direct access to a specific output artifact. |

Limits apply before authentication-heavy work and JSON decoding:

- Maximum request or response body: **64 KiB**, including any message batch.
- Maximum nesting: **12**; maximum batch: **16 messages**.
- Safe integer counters and timestamps only; reject overflow, fractional counters and coercion.
- Reject duplicate keys, noncanonical serialization, unknown core fields and unsupported message types.
- No binary media, base64 media, arbitrary callback URL or executable payload fields.
- Long poll: at most **20 seconds**; ordinary control request deadline: **5 seconds**.

These are proposed initial limits, not measured capacity claims.

### 2.2 Common envelope

| Field | Rule |
| --- | --- |
| `protocol` | Exact constant `nuvioweb.compute`. |
| `version` | Exact negotiated version, initially `1.0`. |
| `type` | Closed message-type enumeration. |
| `messageId` | Random identifier with at least 128 bits of entropy. |
| `correlationId` | Original command identifier for replies. |
| `connectionId` | Coordinator-issued authenticated connection generation. |
| `sentAt`, `expiresAt` | UTC epoch milliseconds; ordinary message lifetime at most 60 seconds. |
| `jobId` | Required for job messages; coordinator-issued. |
| `attemptId`, `fence` | Required after assignment; bind the current execution attempt. |
| `sequence` | Monotonic per sender/attempt for agent events. |
| `expectedRevision` | Required for state-changing commands. |
| `payload` | Exactly one schema selected by `type`. |

Identity is derived from authenticated context. The envelope cannot select its own account or override an agent binding.

A `principalRef` included in grants is an opaque coordinator mapping to the authoritative principal. It is not an additional account identity and is not accepted as client authority.

**Acknowledgment:** return `messageId`, accepted sequence, authoritative job revision, state and a fixed outcome code. Acknowledgment occurs only after the relevant durable transaction commits.

**Errors:** fixed `code`, `scope`, `retryable` and optional bounded `retryAfterMs`. Never return raw exceptions, upstream response bodies, FFmpeg stderr, URLs or arbitrary agent text.

Suggested codes include `INVALID_MESSAGE`, `VERSION_UNSUPPORTED`, `UNAUTHENTICATED`, `FORBIDDEN`, `STALE_REVISION`, `IDEMPOTENCY_CONFLICT`, `LEASE_EXPIRED`, `AGENT_REVOKED`, `LIMIT_EXCEEDED`, `SOURCE_EXPIRED`, `INTEGRITY_FAILED`, `AGENT_LOST` and `HOSTED_DISABLED`.

### 2.3 Negotiation and capabilities

`hello` advertises exact supported versions, required features, optional features and a bounded executor capability description. `welcome` selects one exact version, enabled features, connection generation and applicable limits.

Rules:

- Select the highest common exact version permitted by local policy.
- No common version or missing required feature means rejection before job creation.
- Never silently downgrade security requirements.
- Bind selected version and capability digest into every execution lease.
- Capability updates affect future offers only.
- Advertised capabilities are untrusted claims; they cannot expand permissions or quotas.

Capabilities contain enumerated job types, accepted input profiles, output profiles, maximum parallelism and enforceable resource-limit categories. An executor unable to enforce a required limit must reject the offer.

### 2.4 Existing identity and pairing assumptions

#14 must provide a trusted internal authorization result containing the verified trust domain, subject, session reference where supported, verification time, expiry and session status.

Requirements carried into #13:

- Nuvio access tokens reach only an approved verifier through an authorization header. Passwords and refresh tokens never reach the control plane.
- No Nuvio token reaches agents, plugins, source fetchers or telemetry.
- Privileged operations require authoritative verification; decoded claims, cached owner markers and anonymous sessions fail closed.
- `/auth/v1/user` alone does not establish current session liveness. Unknown or unavailable session status cannot authorize pairing or new execution under this design.
- Account/session changes invalidate pending approvals and results from the previous browser session generation.

Pairing assumptions for #14:

- Agent generates its device signing key locally.
- A one-use, expiring challenge binds the agent key fingerprint and registration intent.
- An authenticated browser explicitly approves the exact device, principal and permissions.
- Redemption is atomic, attempt-limited and protected against CSRF and replay.
- Device grants are scoped, revocable and short-lived; possession of a key alone does not establish an account binding.
- Agent requests prove possession of the bound key and bind method, destination, body digest, nonce and expiry.
- Signing algorithms and keys come from pinned policy, never message-supplied key URLs.

For the proposed lease profile, use asymmetric JWS signatures with an explicit Ed25519 allowlist and fixed key identifiers. Reject unsigned tokens, algorithm substitution and remote key discovery. #13 exercises ephemeral fixture keys only; production issuance, key custody and rotation belong to #14.

### 2.5 Source authorization and submission

Keep three concepts distinct:

| Concept | Contents and authority |
| --- | --- |
| `sourceDescriptor` | Version-1 sanitized technical declarations from #10. No processing authority or secrets. |
| `sourceRef` | Opaque, expiring reference to source access already bound to the selected agent and principal. |
| `sourceGrantDigest` | Digest of the immutable source binding and restrictions; included in the execution lease. |

For the initial user-owned profile, the source binding resides on the selected agent. A future authenticated direct browser-to-agent source-binding exchange supplies the locator under explicit sharing consent; the shared coordinator receives only the opaque reference and binding receipt.

The binding receipt covers `sourceRef`, `clientRequestId`, `principalRef`, `agentId`, expiry, allowed source policy and its digest. It is authenticated by the paired agent. Provider credentials remain agent-local; supporting provider-secret export requires a separate scoped decision.

This direct data connectivity is an assumption for #14/#15, not evidence that NAT traversal, browser HTTPS/PNA requirements or installation work. If it is unavailable, fail with a connectivity error; do not introduce an operator relay.

`job.submit` contains:

- `clientRequestId` and `idempotencyKey`.
- Selected `agentId`; `executionMode` must equal `user_owned`.
- `operation`: `probe`, `remux`, `audio_transcode` or `video_transcode`.
- `sourceRef`, binding receipt, `sourceGrantDigest` and sanitized descriptor.
- Enumerated `outputProfile`, explicit track selections and approved operation options.
- Requested resource limits and absolute deadline.
- Consent reference bound to principal, browser session generation, source, operation and selected agent.

No raw command line, FFmpeg argument list, script, filesystem path, environment variable or arbitrary filter expression is accepted.

The initial source profile supports finite HTTPS files and preloaded legal fixtures. Recursive playlists, torrents, local paths and DRM material are unsupported. Later profiles require separate bounded-fetch contracts.

`remux` must request stream copying; audio conversion must preserve video where supported. Video conversion requires an explicit target. Unsupported preservation requirements cause rejection rather than silent downscaling or metadata loss.

### 2.6 Messages and execution lease

| Message | Required payload and effect |
| --- | --- |
| `job.submitted` | Assigned job ID, request digest, revision, effective limits and deadline. Establishes `QUEUED`; execution is not authorized. |
| `job.offer` | Offer ID, attempt ID, fence, immutable job digest, capability digest and acceptance expiry. Does not authorize processing. |
| `job.accept` | Offer ID, matching digests, accepted limits and agent journal reference. Coordinator atomically binds the attempt. |
| `job.accepted` | Signed execution lease and accepted revision. Lost replies are recovered idempotently. |
| `job.reject` | Fixed reason such as unsupported profile, unavailable source or capacity. No processing may have occurred. |
| `job.started` | Lease ID and durable start intent. Agent waits for acknowledgment, then rechecks lease validity before dispatch. |
| `job.progress` | Enumerated phase, optional basis-point progress and cumulative usage counters. Never extends authorization. |
| `lease.renew` | Current lease ID, fence, journal position and usage. Coordinator may issue a bounded replacement lease. |
| `job.cancel` | Cancellation ID, expected revision and fixed reason. Stops renewals and starts teardown. |
| `job.stopped` | Process/fetch shutdown acknowledgment, final usage and remaining cleanup status. |
| `job.result` | Immutable result manifest and final usage. Proposed success, subject to coordinator validation. |
| `job.error` | Fixed failure code, bounded usage and teardown status. |
| `job.cleanup` | Artifact/workspace cleanup acknowledgment for the exact attempt. |
| `agent.reconcile` | Bounded inventory of active attempt IDs, fences and journal positions after reconnect/restart. |

The signed lease binds:

- Issuer, opaque principal reference, agent audience and device-key thumbprint.
- Job ID, attempt ID, fence and lease ID.
- Negotiated protocol and capability digest.
- Immutable request, source-grant and output-policy digests.
- Approved operation and effective resource limits.
- Consent/session generation references and revocation epoch.
- `issuedAt`, `notBefore`, `expiresAt` and absolute job deadline.
- Constant `executionMode: user_owned`.

Lease validity is at most **60 seconds**. Renewal cannot alter the job, increase limits, change executor or extend the absolute deadline. Lease expiry stops execution locally even when the coordinator is unreachable.

### 2.7 Idempotency, replay and expiry

- Submission uniqueness is `(authoritative principal, operation route, idempotencyKey)`.
- Retrying the same immutable request returns the original job; a different digest returns `IDEMPOTENCY_CONFLICT`.
- Cancellation and acceptance have their own idempotent command identities.
- Persist duplicate records before acknowledging mutations.
- An identical repeated agent event returns the recorded acknowledgment without repeating effects.
- Reusing a sequence/message ID with different content is a protocol violation.
- A sequence gap requires reconciliation; events are not silently reordered.
- New connection generations invalidate old connection proofs. Revocation epochs invalidate old grants.
- Expired commands cannot create new effects. A freshly authenticated status lookup can recover an existing outcome.
- Retain idempotency tombstones through the job’s maximum lifetime plus 24 hours. Older expired envelopes remain invalid after tombstone deletion.
- Bound clock uncertainty to five seconds for authentication checks. Skew never extends execution or artifact deadlines.

### 2.8 Artifact handoff

A result manifest contains:

- `jobId`, `attemptId`, `fence` and immutable manifest digest.
- At most eight artifacts.
- Per artifact: random `artifactId`, kind, MIME type, byte length, SHA-256 checksum and expiry.
- Bounded technical output observations, clearly distinguished from provider declarations.
- Final cumulative resource usage and cleanup status.

Rules:

- A probe returns a bounded technical report; it need not produce media.
- The initial profile publishes finalized files only. Live segmented output is deferred.
- The agent finalizes and hashes each artifact before proposing success.
- Publication atomically binds the manifest to the winning job attempt.
- Direct artifact access uses a short-lived, separately scoped capability binding principal, artifact, job, fence, audience, allowed methods, byte/range allowance and expiry.
- Resolve artifact IDs only against the paired agent’s registered direct data origin. Never follow an agent-supplied arbitrary output URL.
- No operator upload, download proxy or object-storage fallback.
- Range reads share an aggregate byte budget; each range does not reset it.
- Browser/account switching prevents old-session capabilities from entering the new session’s player state.
- Checksums detect corruption and substitution; they do not prove an agent is honest or that media is safe. Whole-file verification occurs only after complete receipt.
- Cancellation, revocation and expiry invalidate access and schedule deletion. Already delivered bytes cannot be recalled.

## 3. Strict lifecycle and quota enforcement

### 3.1 Authoritative state machine

The coordinator owns durable state and serializes transitions with compare-and-swap revisions. Agent events request transitions.

| State | Allowed next states | Condition |
| --- | --- | --- |
| `QUEUED` | `OFFERED`, `CANCELLED`, `EXPIRED`, `FAILED` | Admission succeeded; no execution lease exists. |
| `OFFERED` | `ACCEPTED`, `QUEUED`, `REJECTED`, `CANCELLED`, `EXPIRED` | Return to queue only before acceptance and within bounded offer retries. |
| `ACCEPTED` | `RUNNING`, `STOPPING` | Execution lease issued; durable agent journal required. |
| `RUNNING` | `FINALIZING`, `STOPPING` | Progress does not itself change state. |
| `FINALIZING` | `SUCCEEDED`, `STOPPING` | Publish only after ownership, lease, limits and manifest checks pass. |
| `STOPPING` | `CANCELLED`, `EXPIRED`, `FAILED` | Terminal intent is recorded when stopping begins. Success is forbidden. |
| Terminal | None | `SUCCEEDED`, `REJECTED`, `CANCELLED`, `EXPIRED`, `FAILED`. |

Invariants:

1. One immutable principal and request digest per job.
2. At most one accepted execution attempt per job in v1.
3. No work before accepted lease and acknowledged start intent.
4. No renewal, execution or publication after expiry, revocation or cancellation.
5. Terminal outcomes cannot be overwritten by delayed messages.
6. A cancellation committed before success publication wins. A later cancellation returns `ALREADY_TERMINAL`; it cannot rewrite success.
7. Deadline expiry is checked before accepting a transition; a late result cannot win because a sweeper ran late.
8. Unknown state, fence, agent, revision or lease means denial.
9. Admission, quota reservation, state update and acknowledgment must be atomic. A production adapter unable to provide these semantics is unsupported.

Track cleanup separately as `pending`, `confirmed` or `unconfirmed`, with a deadline and reason. A terminal control-plane outcome means authorization has ended; it does not prove a disconnected or malicious agent deleted data.

### 3.2 Initial fixture policy

All values below are proposed conservative defaults for the reference profile, not product limits or performance guarantees. Every executable job must carry explicit finite limits; missing limits deny admission.

| Resource | Initial policy |
| --- | --- |
| Active attempts | One per agent and one per principal. |
| Queue | Two waiting jobs per principal; finite configured global queue. |
| Global execution | Zero unless explicitly enabled for local fixtures. |
| Admission rate | Six submissions/minute/principal, burst two; also enforce agent/global limits. |
| Queue lifetime | 60 seconds. |
| Offer acceptance | 10 seconds; at most two offers before acceptance. |
| Absolute job lifetime | Five minutes from admission. |
| CPU / memory | 120 CPU-seconds; 512 MiB peak memory. |
| Disk | 256 MiB including temporary files and outputs. |
| Input / output | 64 MiB each; eight artifacts; 32 temporary files. |
| Network | 64 MiB source ingress; 128 MiB artifact egress; four connections. |
| Output retention | 15 minutes after completion, never beyond policy/source restrictions. |
| Progress | At most one event/second, 300 events/job; retain only the current cumulative snapshot. |
| Heartbeat | Every 10 seconds; suspect orphan after 30 seconds. |

Effective limits are the minimum of request, principal policy, agent policy and global policy. A declared agent capacity never overrides them.

### 3.3 Enforcement and recovery

- **Deadlines:** use an injected clock for decisions and a monotonic local watchdog for execution. Renewal cannot reset elapsed time or consumed budgets.
- **Cancellation:** abort fetches and input delivery immediately; stop the process tree, escalate to forced termination within ten seconds, and attempt cleanup within fifteen seconds. The real process adapter must later prove these properties.
- **Partitions:** loss of heartbeats stops renewal and marks the agent suspect. The agent must stop at lease expiry.
- **Orphans:** after lease expiry, terminate the control outcome as `FAILED/AGENT_LOST`, invalidate outputs and quarantine the agent. Record cleanup as unconfirmed.
- **Capacity:** do not offer replacement work to a quarantined agent. Release execution reservations only through defined expiry/teardown transactions; bound quarantined records separately.
- **Crash recovery:** journal acceptance and start intent before acknowledging or executing. On restart, terminate surviving work unless a fresh authorized reconciliation explicitly permits continuation.
- **Coordinator recovery:** reconstruct state, reservations, replay records and deadlines from durable records. Lost transient state never creates new authority.
- **Retries:** transport retries repeat the same command with backoff and jitter, at most three immediate attempts. No automatic retry after execution acceptance in v1.
- **Re-execution:** an accepted failed/lost job requires a new job and renewed consent after safe reconciliation. Never move uncertain work to another agent automatically.
- **Cleanup:** sweep expired artifacts and workspaces on startup and periodically. Derive paths internally; never accept deletion paths from messages. Unconfirmed deletion stays visible.

A compromised user-owned machine can ignore a lease. Protocol fencing prevents trusted participants from accepting its late results; it cannot enforce remote physical shutdown.

### 3.4 Bounded telemetry

Operational records may retain the minimum principal binding needed for authorization and reconciliation. Exported telemetry excludes it.

Allow only enumerated event/error codes, protocol version, coarse duration/resource buckets and short-lived random trace IDs.

Exclude Nuvio/device/artifact credentials, pairing codes, source references, media URLs, URL hashes, headers, titles, library IDs, profile names, IP addresses, raw manifests and process stderr.

Reference limits:

- At most 32 sanitized diagnostic records/job, each at most 256 bytes.
- At most 1 MiB local diagnostic ring; 24-hour expiry.
- No diagnostic upload by default.
- No unbounded account/job identifiers as metric labels.
- Separate replay tombstones from diagnostics and enforce retention independently.

## 4. Threat model and negative tests

Use synthetic principals A and B, including a shared-sync-owner case; ephemeral signing keys; a fake clock; and adapters that deny all real network.

| Threat | Concrete mitigation | Required negative assertions |
| --- | --- | --- |
| Malicious agent | Untrusted capabilities/progress, pinned device identity, lease audience, fenced publication, bounded manifests and registered artifact origin. | Wrong agent/key/fence; forged usage; success before start; arbitrary result URL; oversized manifest; late result after cancel; valid checksum over untrusted output does not confer trust. |
| Malicious client | Authoritative principal derivation, per-operation ownership checks, consent binding and closed processing options. | Client-supplied account/owner/profile ignored; A cannot read/cancel B; shared owner does not share grants; forged limits and raw shell/options rejected. |
| Replay | Durable idempotency, expiry, nonce, connection generation and event sequencing. | Reused acceptance, cancellation, pairing receipt and artifact capability; changed-body duplicate; old connection; expired command after tombstone removal. |
| Confused deputy | Bind principal, agent, source, operation, output policy and consent into one lease. | Swap source reference, agent, operation or output profile; redeem grant at wrong route/audience; delayed A approval after switch to B. |
| SSRF | Agent-local source policy, HTTPS allowlist, connection-time address checks, pinned destination resolution and no redirects in initial profile. | Private/loopback/link-local/metadata addresses; IPv4-mapped IPv6; encoded IP forms; DNS rebinding/mixed answers; userinfo; alternate schemes/ports; redirect to forbidden origin. |
| Relay abuse | No generic fetch route; source binding is account/agent/job scoped; only approved processing verbs; bounded artifact access. | Arbitrary URL-to-byte forwarding; callback URLs; request smuggling through headers; unlimited Range reads; header/protocol injection. |
| Resource exhaustion | Admission caps, strict schemas, finite quotas and local watchdog requirements. | Oversized/deep JSON, duplicate keys, huge arrays, integer overflow, progress flood, queue races, output/file explosion, disk/CPU/memory exhaustion and timeout. |
| Entitlement bypass | v1 accepts only `user_owned`; client claims never establish paid authority. | Hosted mode, fake reservation/quote, balance fields and paid fallback all fail before execution. |
| Cost abuse | Finite attempts, aggregate byte budgets, no automatic execution retries and no hosted provisioning adapter. | Lost acknowledgments do not duplicate work; progress/reconnects cannot reset budgets; repeated reads consume shared allowance; hosted requests invoke zero provisioning calls. |
| Session/revocation failure | Fresh verified context, bounded leases, fail-closed renewal and generation checks. | Expired/fake/anonymous session; `/user` succeeds but session is unknown/revoked; verifier timeout; stale response after logout; revoked device cannot accept, renew or publish. |
| Artifact/path abuse | Internally derived paths, ownership-scoped IDs and immutable manifests. | Cross-account artifact access; traversal/symlink escape; checksum/length mismatch; stale fence; expired access; partial output published as complete. |
| Crash/cancellation race | Durable journals, atomic transitions, lease watchdog and separate cleanup evidence. | Crash before/after acceptance/start/publication; cancellation versus result in both orders; partition during teardown; orphan reconnect; cleanup failure never reported as confirmed. |

For #13, resource and network tests prove policy decisions and adapter calls only. Kernel limits, DNS/socket behavior, process-tree termination and real deletion require #15 integration evidence.

## 6. Compatibility and testing without hosted services

### Versioning

- Wire versions are exact major/minor pairs; package patch releases cannot change accepted wire behavior.
- Preserve `v1.0` schemas and golden fixtures after publication.
- A new optional field or feature requires a negotiated minor version; old peers retain their original closed schema.
- Changed state semantics, authorization meaning, required fields, units or enum meanings require a major version.
- Never ignore an unknown security requirement or reinterpret an unknown operation.
- Bind the selected version into leases and durable job records. In-flight jobs keep that version until terminal.
- Test same-version exchange, a future minor paired with the frozen old version, no-common-version rejection and downgrade attempts.
- Downgrade refuses new unsupported jobs and lets compatible jobs finish or expire; it never translates leases into weaker semantics.
- Publish a compatibility matrix distinguishing schema exchange, mock execution, real agent enforcement and browser playback evidence.

### Offline test architecture

Use in-memory message transport and coordinator storage, a restartable fake journal, a deterministic clock and capped fixture artifacts. Inject signing/verifying adapters using ephemeral test keys.

A fixture executor performs only bounded operations on repository-owned legal bytes. It must not call a real identity service, resolve DNS, create a listening service, launch a process or provision infrastructure. Fetch, process and provisioning adapters fail the test if unexpectedly invoked.

Required reproducible scenarios:

1. Complete submission through verified artifact handoff.
2. Duplicate submission and lost acceptance acknowledgment.
3. Unsupported version, operation and hosted mode.
4. Cancellation in every nonterminal state.
5. Deadline/lease expiry and delayed result rejection.
6. Revocation and account switch during pending work.
7. Crash/restart reconciliation without duplicate execution.
8. Cross-principal source/job/artifact denial.
9. Resource exhaustion and bounded diagnostics.
10. Artifact corruption, expiry and unconfirmed cleanup.

Close #13 only after its protected evidence PRs merge and AC1–AC3 are satisfied. Completion means a specified, validated, offline-tested contract and mock executor. Live identity, pairing, process isolation, direct connectivity and legal fixture playback remain #14/#15 work; priced hosted execution remains separately gated M4 work.
