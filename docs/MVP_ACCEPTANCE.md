## Blocking findings and next milestone

1. #7: nonempty Library isolation now has hosted evidence — with one owner-created item in each disposable account, B→A restored A's own item and exposed no B set ([receipt](evidence/identity-library-nonempty-switch-2026-10-19.json)). The older missing-pull barrier is not reproduced; the returning-B failure remains flaky (marker run failed once, immediate read-only repeat passed). App Save/remove propagation, B→A→B reliability, measured expiry/revocation/QR and cross-device deletion remain open; no further marker write is planned. A deterministic synthetic reproduction must precede any sync runtime change.

Initial stale-guard fix passed locally but failed protected CI and4/5 bounded replays. Actual-player explicit/native controls isolated overlay consumption; final72 Router/focus cases and5 complete guest repeats pass, with final full regression/CI recorded in PR49. Protected integration is recorded in [PR49](https://github.com/saurabhhbansal/nuvioweb/pull/49); hosted verification remains separate. [Playback receipt](evidence/browser-mvp-playback-2026-10-19.md).
3. The hosted legal add-on/media/save journey is demonstrated at `1f67867`. Windows Edge guest journey now passes manually with audible audio; Chromium engine coverage remains sufficient for Edge per owner direction. iPhone Safari plays the VP8/Opus demo but rejects native MKV/HEVC/DV/HDR sources. The startup classifier now separates `unsupported-container`, `unsupported-codec`, `header-required`, `network`, `invalid-content` and genuine `startup-stall` from Chromium engine evidence and the bundled player, so the earlier generic reasons no longer occur ([classification evidence](evidence/startup-classification-2026-10-19.md)). Remaining #10 gaps: automated WebKit coverage, multitrack audio, a supported HDR observation, and hosted external-provider CORS.
