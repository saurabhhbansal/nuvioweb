# M2 workstream plan — add-ons and high-fidelity playback

## Goal
Support established HTTP/Stremio add-ons and safely execute supported Nuvio JS plugins; retain original video quality when possible.

## Steps
1. Create legal fixture set with manifests/catalogs/meta/streams/subtitles and 1080p/4K sample media.
2. Define source descriptor with URL, headers, codecs, container, HDR, tracks, subtitles, availability, authorization and media expiry.
3. Test addon install/configuration/profile sync, manifest variants, CORS/mixed-content, errors and partial provider results.
4. Prototype GYK-like bounded QuickJS worker on independent branch; license review; test malicious inputs, API parity and network boundary.
5. Use MediaCapabilities/canPlayType and actual probe, quality preference and source diagnostics.
6. Evaluate native video, HLS.js, DASH.js, Falcon-compatible WebCodecs/WASM local audio/repacking on supported devices.
7. Test original-quality HDR/4K path, audio switching, subtitles, seek/resume, cancellation and browser fallback.

## Done when
Evidence-based device compatibility matrix exists; supported add-ons resolve and play authorized fixtures without mandatory central compute. Unknown and unsupported formats are clearly labeled, not overstated.

## Risks / rollback
Codec support, CSS/subtitle bugs, sandbox or proxy escape, GPU/browser variance; isolate experimental runtime behind flags.

**Decisive request-contract policy**
- **D/I:** Published VLC/Infuse/Android routes expose URLs, not an arbitrary `Authorization`/`Cookie`/`Referer`/`User-Agent`/custom-header map. Unknown Outplayer/Lenna/nPlayer contracts are not proven incapable, but are not permission to invent parameters. Block any declared required headers before launch, copy or playlist export; include subtitle and nested source requirements. Never silently strip them or export Nuvio identity tokens.
- **I:** A source-issued signed URL can be handed off unchanged if independently usable; its query signature is **not header preservation**. Do not manufacture URL credentials from headers. Initial/master authorization does not automatically cover redirect targets, relative manifests, segments, keys, subtitles, range/seek/retry or expiry. Do not send credentials to another host to make playback work.
- **D:** Native mpv invocation/config can express `--http-header-fields`, `--user-agent`, `--referrer` and cookie settings; this does **not** mean a copied URL, `.m3u` or `mpv://URL` conveys those CLI options. Per-file/global option distinctions also preclude assuming safe per-origin credential scope. https://mpv.io/manual/master/
- **D:** VLC M3U parser collects `#EXTVLCOPT` for the following entry, adds options with flags **0** (not trusted), then resets entry state; parsing is not arbitrary-header acceptance or inheritance across the network request graph. https://raw.githubusercontent.com/videolan/vlc/master/modules/demux/playlist/m3u.c
- **D:** VLC `var_OptionParse` rejects options not marked safe when untrusted; accepted input-object variables can be inherited by child objects. That object inheritance is **not** a guarantee for redirect/manifest/segment/key/subtitle HTTP requests or credential scoping. Do not disable safety or emit `EXTVLCOPT` as a credential workaround. Source links follow moving `master`, not a release guarantee. https://raw.githubusercontent.com/videolan/vlc/master/src/misc/variables.c
- **I:** Emit only an inert, sanitized single HTTP(S) URL entry; reject line/control injection rather than allowing extra playlist directives. Warn that signed URLs are bearer capabilities disclosed to the selected app/clipboard/download history. No proxy/relay compensates for missing headers.

**Playback/output and browser feasibility**
- **D:** Infuse documents Apple TV decoded **LPCM up to 7.1/24-bit/48kHz** and **E-AC3 Atmos**; TrueHD Atmos/DTS-X require additional Apple flexibility. Higher sample rates are converted to 48kHz. Decoded TrueHD→LPCM is not TrueHD bitstream passthrough and does not establish preserved Atmos objects; spatial audio is not synonymous with those outputs. https://support.firecore.com/hc/en-us/articles/217735707-Audio-Options-Capabilities
- **I:** MKV container support and an HEVC/HDR marketing label do not prove **HEVC Main10** decoding at a specified resolution/bitrate or correct DV rendering. Verify profiles **5, 7 (MEL/FEL), 8.x** separately, including layer handling/HDR fallback; the only explicit profile declaration found here is Infuse 5/8. Outplayer/Lenna/nPlayer/VLC profile-specific support remains unknown, not universally unsupported.
- **I:** Explicit native navigation can avoid needing browser-native MKV decoding, but neither app launch nor callback validates media fetching/rendering. Browser gesture/prompt/cancel/missing-app behavior remains device-specific. Do not promise universal links/share targets, browser-cookie transfer, installed-app enumeration or timer-based success. Provide help/cancel and manual return/progress fallback; no callback/notification sidecar dependency.
- **Evidence still required:** named app build/OS/SoC + legal MKV/Main10/DV/audio fixture + display/receiver/output chain; disposable-canary request observations across redirects/dependencies/ranges/expiry before any header-support claim. These unexecuted acceptance gates are not satisfied by this research; #148 cannot be closed as real-device interoperability verified.
