### Containers, codecs and adaptive playback

- [`engines/nativeVideoEngine.js`](../../../app/alpha/js/core/player/engines/nativeVideoEngine.js) loads the original URL through the browser media element. `canPlay()` wraps `canPlayType()`, a prediction.
- `PlayerController.getPlaybackEngineCandidates()` orders HLS as hls.js followed by native HLS when reported; DASH as native DASH when reported followed by dash.js. Ordinary files have only `native-file`.
- MIME aliases, extensions and provider fields influence routing through `guessMediaMimeType()`, `normalizePlaybackSourceType()` and `streamScreen.resolveStreamMimeType()`. They do not establish actual codecs.
- [`loadStreamingLibs.js`](../../../app/alpha/js/runtime/loadStreamingLibs.js) loads packaged hls.js 1.5.20 and dash.js 4.7.4, with inherited CDN fallbacks. No decoder/remux dependency should be added through this loader.
- The locally installed hls.js implementation describes MPEG-TS/AAC transmuxing to fragmented MP4. Its `src/demux/tsdemuxer.ts` extracts AVC and AAC samples. This is compressed-sample repackaging, with decoding still performed by browser APIs. It does not make an unsupported audio codec decodable.
- There is no application `localAudioEngine`, general Matroska demuxer, FFmpeg process or general local audio transcoder in the inspected player/stream paths.
- `PlayerController.getPlaybackCapabilities()` contains generic codec probes and `hdrLikely`/`atmosLikely` heuristics. These are not HDR display, Atmos output or device certification.
- [`sourceCapabilities.js`](../../../app/alpha/js/core/streams/sourceCapabilities.js) separates bounded provider declarations from native/optional MediaCapabilities predictions. Its async probe is video-only; missing fields remain unknown.
- `streamRepository.mapStream()` attaches the source descriptor; `streamList.flattenStreams()` revalidates/carries it. Provider audio declarations are not engine-discovered selectable tracks.

### Manifest handling and recovery

`playerScreen.parseHlsManifestTracks()`, `parseDashManifestTracks()`, `loadManifestTrackDataForCurrentStream()`, `pickManifestVariant()` and `applyManifestTrackSelection()` provide inherited manifest metadata and variant handling.

Important limits:

- The side manifest fetch has a five-second timeout around obtaining the response; it subsequently calls `response.text()` without an explicit body-byte cap or a body-inclusive deadline.
- It may try candidate URLs, retry without headers and inspect a nested variant.
- Manifest audio metadata is separate from the engine track list used by `getAudioEntries()`.
- Variant scoring uses resolution, bitrate and capability heuristics. It is not an encoded-quality equivalence check.
- New recovery must not infer that two video renditions are identical because their advertised dimensions match.

`PlayerController.playWithHlsJs()` already contains:

- One application-level nonterminal fatal network recovery through `startLoad()`.
- One fatal media recovery through `recoverMediaError()`.
- Terminal HTTP status handling through [`hlsNetworkErrorPolicy.js`](../../../app/alpha/js/core/player/hlsNetworkErrorPolicy.js): 400, 401, 403, 404 and 410.
- A special fatal level-404 retry, up to two attempts with 1.5 s and 3 s delays; a successful level load resets that counter.
- Fatal manifest-load/timeout propagation rather than ineffective `startLoad()` recovery.
- Library-internal loading policies in addition to these application counters.

These counters are not a single total recovery budget. Preserve established behavior outside the opt-in prototype.

`PlayerScreen.bindVideoEvents()` handles native direct-child `SOURCE` errors, ignores unrelated `TRACK` errors and may switch to an unattempted engine during startup. `schedulePlaybackStallGuard()` uses startup/in-playback timeouts and can attempt another engine. In-playback source replacement otherwise remains user initiated.

An inspected in-playback warning still logs `{ url: this.activePlaybackUrl }`. Extend redaction coverage before routing new recovery failures through it; existing startup redaction does not prove every warning is safe.

[`addonFailure.js`](../../../app/alpha/js/data/remote/addonFailure.js): `describeAddonFetchFailure()` normalizes add-on installation failures without an HTTP code. It is not a media error classifier. Its status-less network message acknowledges connection/CORS ambiguity; do not reuse its regular expressions to diagnose audio decode failures.

## 3. Scope and acceptance interpretation

Implement a bounded browser prototype with two supported routes:

1. **Audio recovery:** explicitly select a compatible alternate audio rendition while retaining the same video representation; confirm selection and resumed decoded audio.
2. **Container recovery:** demonstrate the existing hls.js MPEG-TS → fragmented-MP4 path with original H.264/AAC samples and browser decoding.

The smallest useful audio problem is a failed/unavailable selected rendition with a working compatible alternate. This is recovery by alternate-track selection. It is **not AC-3/E-AC-3/DTS conversion**.

### Acceptance mapping

| ID | Issue criterion | Required evidence |
| --- | --- | --- |
| AC1 | Supported audio problem fixed locally on eligible devices | Real selected-audio failure → explicit alternate selection → engine confirmation, advancing video and decoded alternate-audio signal; no remote processing |
| AC2 | Video resolution/HDR remains original where technically possible | Same selected video representation and compressed-sample evidence; original dimensions/time/seek. No HDR preservation claim without an HDR fixture and named-device evidence |
| AC3 | Unsupported/browser-specific cases honestly described | Tested messages and return paths for missing APIs, codec rejection, no alternate, CORS/access failure and exhausted budgets |

If issue acceptance requires decoding an AC-3/E-AC-3/DTS-only source locally, these units leave AC1 **partially satisfied**. Do not close the issue by relabeling alternate-track recovery as codec conversion. Resolve that requirement explicitly in the issue and evidence PR.

### Non-goals

- No central media relay, CORS proxy, backend, native FFmpeg process, paid service or hosted/user-agent compute.
- No DRM circumvention, EME/key-system additions, decryption feature or restriction bypass.
- No video re-encoding, scaling, tone mapping or silent lower-quality fallback.
- No arbitrary MP4/MKV/AVI/standalone-TS repair, full-file download/remux or multi-gigabyte buffering.
- No automatic detection of “inaudible” media from muted playback, absent track APIs or analyser silence.
- No promise of surround passthrough, Atmos objects, lossless output, hardware decoding or universal browser support.
- No new authentication, credential forwarding, plugin execution or dependency on #11.
- No production deployment or preview refresh as part of this issue.

| --- | --- | --- | --- |

| DASH/fMP4 | H.264 video adaptation plus separate AAC audio adaptations | dash.js/MSE | Verify real manual selection/confirmation. Automatic DASH recovery is deferred until its failure attribution is demonstrated |
| MP4/HLS/DASH | HEVC or AV1 + supported audio | Exact native/MSE configuration only | Conditional direct playback; not an initial recovery fixture. No decoder is added |

| Encrypted/restricted media | Any | Outside recovery prototype | “Local recovery is unavailable for this source.” No key fetch or bypass |
| Unknown codec/layout | Any | Existing direct attempt or deliberate user selection | “Audio compatibility is unknown.” Do not invent AAC, stereo or decoder failure |

### Multitrack semantics

- Engine tracks are selectable entities; provider declarations and separately parsed manifest labels are descriptive evidence.
- Identify tracks by source generation, engine and an opaque engine track identity. Index is only a current-list adapter detail.
- Distinguish language, role/commentary/audio-description, codec, layout and default status when supplied. Missing values remain unknown.
- Handle duplicate IDs/labels and reordered lists without selecting the wrong rendition. Ambiguous identity must fail closed.
- Existing preferences guide startup. Explicit user selection takes precedence.
- Automatic preference matching must not substitute commentary, audio description or another language as “equivalent recovery.”
- A codec/layout change must be disclosed. Switching from a surround rendition to stereo preserves the video, not the original audio presentation.
- A setter returning `true`, a locally emitted change event or a checkmark is not completion.
- On failed selection, restore the last confirmed track once when still eligible. If restoration fails, show failure and allow another track/source or Go Back. Never loop.

### Meaning of “quality-preserving”

- **Remux:** compressed samples are repackaged without video/audio encoding. Container bytes and timestamps may legitimately differ; compressed payload preservation needs sample-level evidence.
- **Alternate audio:** the original selected video is retained. The replacement audio is a different rendition and is labeled accordingly.
- **HLS variant fallback:** another rendition with equal dimensions can still differ in bitrate, codec, color or mastering. It is not automatically quality-preserving.
- During prototype audio recovery, pin the existing video level/representation. Restore its prior ABR/manual policy after success, cancellation or failure.
- Outside that bounded operation, inherited ABR remains. Do not claim whole-session original-quality locking.
- No HDR preservation claim follows from dimensions, Main10 support or `hdrLikely`. HDR source metadata, rendering and display evidence are separate.

### Selection contract

Add alongside existing controller methods:

```js
selectBrowserAudioTrack({
  generation,
  trackKey,
  signal
}) -> Promise<{
  status,                 // confirmed | rejected | timed-out | cancelled
  generation,
  trackKey,
  previousTrackKey,
  reason                  // fixed enum; no raw URL/provider body
}>
```

- Existing synchronous setters remain adapter primitives.
- `confirmed` means the corresponding engine reports the selected/rendered track; decoded signal remains a separate test observation.
- HLS confirmation comes from SDK callbacks, not `setHlsAudioTrack()`’s immediate synthetic event.
- DASH confirmation uses actual current/rendered track events plus identity re-read.
- Native confirmation re-reads selection state; without a usable track API return unavailable.
- One pending selection; a newer request cancels the earlier one.
- Default confirmation deadline: five seconds. Source change, stop, navigation and profile/account change invalidate the generation.
- No automatic retry of a failed rendition.

```js
planAudioRecovery({
  generation,

  failedTrackKey,
  lastConfirmedTrackKey,
  failure,
  attempts,
  userChoice

  action,                 // offer-track | restore-track | unsupported | none

```

Pure function; no fetch, player mutation, persistence or logging. A generic media error must not be classified as audio-only without attributable engine evidence.

## 8. Browser assertions and evidence design

### Actual decoded audio

Use complementary observations:

1. The expected engine track identity is confirmed.
2. Requests identify the selected rendition’s actual fixture payload.
3. Video time advances without a media error.
4. Where capture is available, a test-only Web Audio analyser observes the fixture’s expected tone.

For the analyser:

- Use a user gesture to resume the audio context; record its state.
- Attach only once per media element and avoid conflict with the existing amplification graph.
- Use same-origin/MSE or explicitly CORS-enabled fixtures. Do not change ordinary native cross-origin loading to make capture work.
- Establish a positive decoded-signal control before switching.
- Require the expected 440/880 Hz signal in multiple post-switch windows after buffered old audio has passed.
- Treat zero signal as inconclusive until capture, CORS, context, mute/gain and timing are controlled.
- Do not ship analyser-based silence detection.

An engine event alone proves selection state. A validated analyser signal proves decoded digital audio reached that observation point. Neither proves speakers produced audible sound.

### Unit 2 — first step executed: normalized track evidence (2026-10-19)

Status: the observation half of unit 2 is implemented; the async selection seam and the presentation strings are not.

**What exists.** `app/alpha/js/core/player/browserAudioTracks.js` is a pure module (no DOM, network, storage or logging) implementing the §5 observation contract:

- `normalizeEngineAudioTracks({engine, generation, tracks, selectedIndex, decodePredictions, hasSetter})` returns per-track `{generation, key, engine, engineTrackId, index, language, role, label, codec, channels, selected, selectability, decodeSupport, metadataEvidence, ambiguous}` plus `{trackCount, availableCount, unavailableCount, unknownCount, ambiguousCount, predictedCount, selectedKey}`.

### Recovery policy executed (2026-10-19)

Status: the pure planner exists and was hardened after review; nothing calls it yet and no recovery operation is wired.

**Contract change recorded in review.** The plan's draft contract had a `userChoice` input. Review found that it let an explicit choice bypass attribution, container rejection and the attempt caps. `userChoice` is therefore **removed**: explicit selection is not automatic recovery, it may cross language and role, and it belongs to the selection path (`resolveAudioSelectionRequest` in `browserAudioTracks.js`) with its own pending-selection state. The planner now answers only "what may be offered automatically?".

**What exists.** `app/alpha/js/core/player/playbackRecoveryPolicy.js` — `planAudioRecovery({generation, currentGeneration, tracks, failedTrackKey, lastConfirmedTrackKey, failure, attempts}) → {action, trackKey, reason}` with fixed `action` (`offer-track` | `restore-track` | `unsupported` | `none`) and a fixed reason enum. Pure: no fetch, mutation, persistence or logging; every field it relies on is read as an own data property; hostile input is bounded or rejected rather than thrown at.

**Rules it enforces.**

- No failure → `none`/`no-failure`; a stale generation or track snapshot → `none`/`generation-changed`.
- A failure is only recoverable as audio when `failure.audioAttributable` is exactly `true`; a generic or unknown media error, a missing flag or a non-boolean flag never yields a track offer.
- A container failure → `unsupported`/`unsupported-format`; an empty list → `unsupported`/`no-tracks`.
- Lists are capped at 32; a duplicate or flagged-ambiguous failed identity, or a duplicated alternate/restore key, fails closed instead of guessing; keys are validated without truncation, so an oversized key cannot alias a shorter one.
- Counters must be own non-negative integers ≤ 1000; a malformed counter is invalid state, not zero, so bad state cannot re-open the budget.
- Automatic matching requires the **same role and same language**, and an unspecified language only matches another unspecified language. A playback failure may not fall back across language or role; restoring the previous user-selected rendition after a *selection* failure is the documented, capped exception.
- One alternate offer and one restore attempt per operation, distinguished in the reason (`no-alternate` vs `alternate-tried`/`restore-tried`).
- Replay protection and operation identity are the caller's responsibility; a pure planner cannot prevent identical inputs being planned again, and the module says so.

**Verification.** `node --test app/alpha/js/core/player/playbackRecoveryPolicy.test.mjs` 16/16, including the review's discriminating cases: a valid unknown→unknown match, simultaneous alternate/restore eligibility, a colliding 160/168-character prefix pair, duplicate candidate/restore keys, accessor-backed and inherited inputs, malformed counters, the 32-track boundary, and purity under frozen inputs. `npm test --prefix app/alpha` 1307/1307; lint pass.

### Recovery operation state executed (2026-10-19)

Status: the caller-side operation record exists and was hardened after review; nothing calls it yet.

**Why.** The loader review noted that a pure planner cannot stop a caller replaying identical plans, and that "one alternate, one restore" needs an owner. `app/alpha/js/core/player/recoveryOperation.js` is that owner. Pure: no network, no player mutation, no persistence, no logging.

**Contract.** `createRecoveryOperation({generation})` → `begin(key, generation?)`, `offerAlternate(key, generation?)`, `offerRestore(key, generation?)`, `canOffer(kind, key, generation?)`, `close(reason)`, `invalidate(generation, reason?)`, `isCurrent(generation)`, `snapshot()`.

**Rules (after review).**

- A generation must be a positive **safe integer number**; numeric strings, floats, `NaN`, infinities, values beyond safe-integer precision and non-numbers are `invalid-request`, and an invalid operation refuses every action, `isCurrent` and `invalidate`.
- Nothing is offerable before `begin`; `begin` records the failed track exactly once.
- The failed track is never a recovery target (alternate *or* restore).
- One alternate and one restore per operation; the limits are fixed, not configurable, because the plan's invariant is one of each.
- A previously attempted track is refused as `already-attempted`, so "offer A, then restore A" cannot happen.
- `canOffer` runs the same eligibility function as the offer methods, so it cannot report permission an offer would refuse.
- Reasons are a fixed enum; an unknown value normalizes to `operation-closed`, a successful `invalidate` returns the stored reason, and an already-closed operation returns `operation-closed` rather than echoing new input.
- Every action takes the caller's generation and refuses a mismatch as `stale-generation`, so a stale holder cannot act after its `invalidate` was refused.
- Keys are validated without truncation; snapshots are deep copies; attempts record their kind and order.

**Verification.** `node --test app/alpha/js/core/player/recoveryOperation.test.mjs` 14/14, including the review's previously unprotected guards; `npm test --prefix app/alpha` 1321/1321; lint pass. Record: [review](../../agent-runs/2026-10-19-recovery-operation-review.md).
